# Workloads the deep walk SKIPS, and why. One per line: an id, whitespace, a
# reason. Comments and blank lines are ignored.
#
# This exists because the walk remembers successes and nothing else. Without it a
# workload whose cause is already understood is re-attempted on every pass, and at
# roughly fifteen minutes each a handful of them consume hours before the walk
# reaches anything new — which is exactly what happened: authentik alone was
# attempted eleven times in one day, and a third of all attempts were repeats.
#
# A skip is NOT a pass. Every entry is printed at the start and end of the run,
# the walk exits non-zero if any exist, and none of them counts as delivered.
# The point is to stop paying for a diagnosis already made, not to hide it.
#
#   RETRY=1 ./hack/smoke/deep-run.sh          attempt these as well
#   ./hack/smoke/deep-run.sh authentik        naming one explicitly always runs it
#
# Remove an entry the moment its cause is fixed; a stale one hides a workload that
# would now pass. The walk says so if a skipped workload is run and delivers.

authentik    two replicas race the first-boot migration on a lock, so the second overruns its startup probe; needs ordered start, not a longer timeout, and authentik exposes no standalone migration command
bigcapital   docker.io/bigcapitalhq/gateway does not exist (siblings server/webapp do); needs upstream's intent, not a guessed name
ghostfolio   never becomes ready, zero restarts, no container output at all; needs live inspection of /api/v1/health like baserow had
lychee       FrankenPHP workers fail to initialise; the FRANKENPHP_* settings that used to work no longer do, so it wants upstream's current compose rather than another guess
mailu        the admin container refuses to start without a DNSSEC-validating resolver, which the catalogue does not ship; upstream runs unbound alongside
mongo-express  needs a MongoDB server, which cannot run on this host's kernel (see mongo)
overleaf     needs MongoDB (unverifiable here), and its secretKeys omit OVERLEAF_INVITE_TOKEN_SECRET, which it refuses to start without
owntracks-recorder  dies dialling an MQTT broker at localhost:1883 while the catalogue declares no dependency; the default render is not the standalone mode its own docs describe
prestashop   its entrypoint reaches the database now (the engine override fixed that) but exits on "Another setup is currently running" on a FIRST boot in an empty namespace, with replicas already 1 — so it is not the two-replica install race authentik has, and clearing it needs upstream's install flow rather than another guess
projectsend  its s6 init exits during 30-config, straight after "New container detected. Setting up app folder and fixing permissions", printing no error at all; every linuxserver relaxation is already granted (rootUser, allowPrivilegeEscalation, keepCapabilities, writable rootfs), so the usual cause is ruled out and this needs live inspection of that script
rocketchat   MongoDB-only, and MongoDB cannot run on this host's kernel (see mongo); it was failing in its Mongo driver after being handed a PostgreSQL, because the catalogue records only `database: required` and cannot yet say which engine
wekan        reads MONGO_URL and needs MongoDB, which cannot run on this host's kernel (see mongo); it also declares no secretKeys, so the harness minted no Secret and the pods sat in CreateContainerConfigError
znc          refuses to start on an empty volume: "Opening config [/znc-data/configs/znc.conf]... [ No such file ]. Restart ZNC with the --makeconf option", which is interactive — so a first boot needs an operator-supplied znc.conf, and kurly authors none
opencost     starts and is then killed by its own liveness probe on /healthz within seconds, repeatedly. Its only configured dependency is a Prometheus at prometheus-operated.monitoring.svc:9090, which the walk never stands up — and `requires` has no vocabulary for a metrics backend, so nothing declares it. Needs either a Prometheus prerequisite or evidence that /healthz is unrelated to it
